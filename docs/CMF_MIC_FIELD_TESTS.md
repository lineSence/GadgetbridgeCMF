# Микрофон часов: результаты полевых тестов

> Устройство: **CMF Watch Pro 2**, прошивка `1.0.0.73`, S/N `CI04102520008192`
> Телефон: **TECNO LF7n**, Android 12 (API 31)
> Дата: **2026-09-09**
> Инструмент: `CmfSourceProbe` + `CmfTelecomCallShim` (ветка `feature/cmf-mic-recorder`)

---

## Итог

**SCO-канал вне звонка работает. Микрофон часов не работает.**

Часы принимают соединение, держат его и передают кадры. В кадрах нет звука. Это верно и вне звонка, и при активном звонке. Гипотеза «микрофон открывается по индикации звонка HFP» **опровергнута**.

| Проверка | Результат |
|----------|-----------|
| SCO вне звонка (`isBluetoothScoAvailableOffCall`) | ✅ поддерживается |
| Подъём SCO-канала | ✅ работает |
| Часы как вход `BLUETOOTH_SCO` | ✅ видны системе (`CMF Watch Pro 2-502D`) |
| Поток данных от часов | ✅ идёт, ~38–78 КБ за 2,5 с |
| Звук в потоке | ❌ нет, максимум `peak = 8` из 32767 |
| Звук при активном звонке | ❌ нет |

`peak = 8` при 16 битах — это около −72 дБ. Это шум младших разрядов, а не сигнал.

---

## Тест 1 — скан вне звонка

**Условия:** SCO поднят вручную, режимы `MODE_IN_COMMUNICATION` и `MODE_IN_CALL`.

**Результат:** тишина во всех 14 комбинациях (7 источников × 2 частоты), максимум `peak = 8`.

**Замечание:** в этом прогоне не проверялся фактический маршрут захвата. Поэтому результат сам по себе не был доказательным.

---

## Тест 2 — имитация звонка, маршрут не ушёл на часы

**Условия:** self-managed звонок Telecom, часы не подключены по профилю hands-free.

```
callActive=true
callRoute=earpiece
scoInputAvailable=false
preferredInput=нет SCO-входа
```

**Результат:** ложноположительный. Максимум `peak = 6267` на `DEFAULT @ 16000`.

**Причина:** SCO-входа в системе не было, Android взял встроенный микрофон телефона. Записана комната, а не часы.

**Вывод для инструмента:** уровень сигнала без проверки маршрута ничего не значит. В `CmfSourceProbe` добавлена колонка фактического устройства захвата (`AudioRecord.getRoutedDevice()`). В зачёт идут только строки с `BT_SCO`.

---

## Тест 3 — имитация звонка, маршрут на часах ✅ чистый прогон

**Условия:** часы подключены как гарнитура, self-managed звонок Telecom активен, маршрут подтверждён.

```
strategy=self-managed Telecom call
inputDevices=телефон, BT_SCO, telephony, телефон, type25, type16, type28
callActive=true
callRoute=bluetooth
audioMode=3           (MODE_IN_CALL)
scoInputAvailable=true
preferredInput=CMF Watch Pro 2-502D (id 3834)
```

| Источник | Частота | Байт | peak | rms | Устройство |
|----------|---------|------|------|-----|------------|
| VOICE_COMMUNICATION | 16000 | 39680 | 7 | 2 | BT_SCO |
| VOICE_COMMUNICATION | 8000 | 38400 | 8 | 2 | BT_SCO |
| VOICE_RECOGNITION | 16000 | 67840 | 0 | 0 | BT_SCO |
| VOICE_RECOGNITION | 8000 | 37760 | 0 | 0 | BT_SCO |
| MIC | 16000 | 76800 | 0 | 0 | BT_SCO |
| MIC | 8000 | 37760 | 0 | 0 | BT_SCO |
| DEFAULT | 16000 | 70400 | 0 | 0 | BT_SCO |
| DEFAULT | 8000 | 36480 | 0 | 0 | BT_SCO |
| CAMCORDER | 16000 | 71680 | 0 | 0 | BT_SCO |
| CAMCORDER | 8000 | 37120 | 0 | 0 | BT_SCO |
| VOICE_CALL | 16000 / 8000 | 0 | — | — | источник недоступен |
| VOICE_UPLINK | 16000 / 8000 | 0 | — | — | источник недоступен |

**Что доказано этим прогоном:**

1. Маршрут захвата — реально часы, а не телефон (колонка `BT_SCO`).
2. Часы получили индикацию активного звонка (`audioMode=3`, `callRoute=bluetooth`).
3. Данные идут, но они пустые. Ровно нули на всех источниках кроме `VOICE_COMMUNICATION`, где виден только шум квантования.
4. `VOICE_CALL` и `VOICE_UPLINK` недоступны приложению. Эти источники требуют системных прав, обойти нельзя.

**Примечание:** `bluetoothScoOn=false` при `callRoute=bluetooth` — это норма. При self-managed звонке каналом управляет Telecom, а не флаг устаревшего API.

## Толкование

Возможны два объяснения. Различить их без дампа прошивки нельзя.

1. **Аплинк закрыт в прошивке.** Прошивка поднимает SCO и отдаёт кадры-заполнители, но не подключает микрофон к аудио-DSP. Это согласуется с известным фактом: голосовые функции на этом SKU отключены (`ux2sys 0x9e`, флаг `908b = 00`).
2. **Нужен полноценный телефонный звонок.** Часы могут открывать микрофон только после AT-обмена с реальным телефонным стеком (`AT+CIEV` от сети, а не от self-managed звонка).

Второе проверяется одним ручным тестом: позвонить на телефон, принять звонок **на часах**, говорить в часы. Если собеседник вас слышит — микрофон физически работает, и вопрос только в способе его открыть. Если не слышит — микрофон закрыт в прошивке, и уровень A закрыт полностью.

## Влияние на карту возможностей

В `docs/CMF_CAPABILITIES.md` раздел 0 требует правки:

* пункт 1 «Диктофон через микрофон часов» — статус меняется с «PoC в этой ветке» на **«канал есть, микрофон закрыт»**;
* пункт 2 «Озвучка/TTS в динамик часов» — **не проверено**. Аплинк и даунлинк независимы. Динамик может работать даже при закрытом микрофоне. Это следующий тест;
* фраза «микрофон и динамик часов доступны прямо сейчас» неверна для микрофона.

## Инструменты, которыми получены данные

| Файл | Назначение |
|------|------------|
| `CmfSourceProbe` | скан 7 источников × 2 частоты, проверка фактического маршрута захвата |
| `CmfTelecomCallShim` | self-managed звонок Telecom, чтобы часы считали звонок активным |
| `CmfScoAudioLink` | подъём и освобождение SCO-канала |
| `CmfRecorderActivity` | запуск всех тестов с экрана телефона, без adb |

Отчёты сохраняются как `cmf-probe-<дата>.txt` в папке вывода диктофона.
