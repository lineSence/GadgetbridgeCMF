# CMF Watch Pro 2 — карта возможностей

> Что можно выжать из часов сверх функционала Nothing X, и как это сделать в этом форке.
>
> Обновлено: **2026-09-09** · Целевое устройство: **CMF Watch Pro 2** (`ATS3089C`, Zephyr + LVGL)
> Тестовый экземпляр: прошивка `1.0.0.73`, S/N `CI04102520008192`

| 1 | **Диктофон через микрофон часов** (запись на телефон) | A — BT Classic HFP/SCO | 🟢 нулевой | PoC в этой ветке |

| 5 | **Сырые датчики: акселерометр, NTC, HR/HRV/SpO2 по требованию** | B — AT-канал | 🟢 низкий | реализуемо |
| 6 | **Вибромотор, экран, GPS, кнопки как API** | B — AT-канал | 🟡 средний | реализуемо |
| 7 | **~25 неиспользованных опкодов** (мировые часы, задачи, ДНД, карточки) | B — BLE | 🟢 низкий | не реализовано |

| 9 | **Чтение/запись flash и RAM, своя прошивка** | C — Zephyr shell | 🔴 кирпич | только recon |

Главный вывод: **микрофон и динамик часов доступны прямо сейчас, без вмешательства в прошивку.** Часы поддерживают профиль **HFP-HF**, а значит телефон может поднять SCO-канал вне звонка и читать/писать аудио штатными Android API. Всё остальное «сверх Nothing X» делится на безопасный BLE-слой (кастомизация UI и датчики) и рискованный слой Zephyr shell (flash/прошивка).

## 1. Аппаратная база

| Компонент | Что известно |
|-----------|--------------|
| SoC | **Actions ATS3089C**, Cortex-M4, встроенный BT Classic + BLE, аудио-DSP |
| ОС / UI | **Zephyr RTOS** + **LVGL** (порт `lv_port_actions_technology`), FS: FatFS + SDFS |
| Экран | 1.32″ AMOLED, **466×466**; для фото-циферблатов активная область по `RESOLUTION_GET (FFFF 907F)` → **466×360** |
| Датчики | PPG (пульс, SpO2, стресс, HRV), **3-осевой акселерометр**, **GNSS** (+AGPS), внутренний **NTC**-термистор |
| Нет | барометра, компаса, гироскопа, датчика темп. кожи, ЭКГ, NFC |
| Аудио | **микрофон + динамик**; профиль **HFP-HF** (звонки) есть. **A2DP-sink нет** — музыку в часы не отдать |
| Отладка | UART-консоль Zephyr на плате + **shell поверх BLE** (сервис `77d4e67c…`) |
| OTA | **без подписи**, целостность только CRC32 |

## 2. Три уровня доступа

### Уровень A — BT Classic (HFP / SCO) 🟢

Часы для телефона — обычная **Bluetooth-гарнитура**. Значит доступны:

* `BluetoothProfile.HEADSET` — состояние подключения, audio-state;
* **SCO-канал вне звонка** (`isBluetoothScoAvailableOffCall()`), а на Android 12+ — современный `AudioManager.setCommunicationDevice(TYPE_BLUETOOTH_SCO)`;
* после поднятия канала: `AudioRecord` (микрофон часов) и `AudioTrack`/TTS (динамик часов).

Ничего не патчится, прошивка не трогается, гарантия и OTA целы. **Это фундамент диктофона.**

### Уровень B — кадрированный BLE-протокол 🟢

Основной канал управления, который уже использует Gadgetbridge:

| Назначение | UUID |
|------------|------|
| Команды | сервис `0000fff0-…`, запись `fff2`, нотификации `fff1` |
| Массовые данные (циферблаты, прошивка, AGPS) | `02f00000-…-ffe0` + `ffe1` / `ffe2` |
| Прошивка | `02f00000-…-fe00` + `ff01` / `ff02` |
| AT-канал | сервис `77d4e67c-…`, запись `77d4ff01`, нотификации `77d4ff02` |

Кадр: `0xF5 | len(u16 BE) | cmd1(u16 BE) | chunkCount | chunkIndex | cmd2(u16 BE)`, тело = `payload ‖ CRC32-LE`, шифрование **AES-128-CBC/PKCS7** с фиксированным IV; сессионный ключ — `SHA256(nonce ‖ authkey)[0..16]`. Открытым текстом идут только `AUTH_*` и чанки заливки данных.

Важно: `TIME (FFFF 8004)` — «затвор» протокола, до его отправки часы игнорируют все запросы данных.

### Уровень C — Zephyr shell поверх BLE 🔴

Через AT/shell-сервис доступны команды отладочной консоли Zephyr:

| Команда | Что делает |
|---------|-----------|
| `mdw <addr> <count>` / `mww <addr> <val>` | чтение / запись RAM и регистров |
| `snandr <off> <size>` / `snandw <off> <size>` | чтение / запись SPI-NAND |
| `sdfs <name> <size>` | работа с SDFS-разделом (ресурсы, рингтоны) |
| `fread` | чтение файла |

Это полный доступ к железу: свои рингтоны, подмена ресурсов, теоретически — своя прошивка и диктофон «внутри» часов. И это же — прямой путь к кирпичу.

## 3. Диктофон

### 3.1 Вариант 1 — запись через SCO на телефон ✅ рекомендуется

**Идея:** часы остаются гарнитурой, аудио пишется на телефоне. Прошивка не меняется.

**Поток:**

1. `BluetoothAdapter.getProfileProxy(…, BluetoothProfile.HEADSET)` — убедиться, что часы подключены как гарнитура.
2. Проверить `AudioManager.isBluetoothScoAvailableOffCall()`.
3. Поднять канал:
   * **Android 12+ (API 31):** `setMode(MODE_IN_COMMUNICATION)` → `getAvailableCommunicationDevices()` → найти `TYPE_BLUETOOTH_SCO` → `setCommunicationDevice(dev)`;
   * **старые версии:** `setMode(MODE_IN_COMMUNICATION)` → `startBluetoothSco()` + `setBluetoothScoOn(true)`, ждать `ACTION_SCO_AUDIO_STATE_UPDATED` → `SCO_AUDIO_STATE_CONNECTED`.
4. `AudioRecord(MediaRecorder.AudioSource.VOICE_RECOGNITION, 16000 → fallback 8000, CHANNEL_IN_MONO, ENCODING_PCM_16BIT)`.
5. Писать в WAV (или кодировать в Opus) из foreground-сервиса типа `microphone`.
6. На выходе — `clearCommunicationDevice()` / `stopBluetoothSco()` + `setMode(MODE_NORMAL)`.

**Разрешения:** `RECORD_AUDIO`, `BLUETOOTH_CONNECT`, `FOREGROUND_SERVICE_MICROPHONE` (API 34+), `POST_NOTIFICATIONS`.

**Управление с часов без правки прошивки:**

| Событие часов | Опкод | Как использовать |
|---------------|-------|------------------|
| Кнопки плеера (play/pause/next) | `MUSIC_BUTTON FFFF A05D` | старт / пауза / метка |
| «Найти телефон» | `FIND_PHONE 005B 0001` | аварийный стоп |
| Экран плеера | `MUSIC_INFO_SET FFFF 905C` (131 Б: `state｜volume｜volumeMax｜track[64]｜artist[64]`) | индикатор `REC ● 00:42` на часах |
| Вибро-подтверждение | `AT SETMOTOR=1` | тактильный отклик старта/стопа |

То есть **экран плеера превращается в UI диктофона**, а его кнопки — в кнопки записи.

**Ограничения (физика профиля):**

* моно, **8 кГц CVSD** либо **16 кГц mSBC** — качество телефонного разговора, не подкаст;
* в тракте HFP работает **шумоподавление под речь**: музыка, шум природы, «эмбиенс» будут искажены;
* система считает, что идёт разговор: возможен экран звонка, приглушение остального аудио, обрыв при входящем звонке;
* растёт расход батареи часов (SCO-радио).

**🟡 Не подтверждено на этой модели:** разрешает ли прошивка часов SCO **вне звонка**. Это первое, что проверяет PoC — см. `docs/CMF_MIC_RECORDER.md`.

### 3.2 Вариант 2 — диктофон внутри прошивки 🔴

В семействе устройств функция записи существует: у **Watch 3 Pro** есть штатный рекордер с транскрипцией. У Pro 2 голосовые функции **программно отключены**: подсистема `ux2sys` id `0x9e`, флаг поддержки `908b = 00`.

Поскольку OTA не подписана (только CRC32), теоретически можно собрать образ с включённым рекордером. Практически: другой набор ресурсов/разделов, высокий шанс кирпича или сброса к заводским. Только после полного дампа flash и наличия способа восстановления.

### 3.3 Вариант 3 — гибрид

Запись по SCO на телефон + управление и индикация на часах через `MUSIC_*` опкоды + вибро через AT. Это ровно то, что даёт Вариант 1 без правки прошивки, — оптимальное соотношение риск/результат.

## 4. Звук из часов (динамик)

Тот же SCO-канал работает в обратную сторону:

* **TTS в часы** — уведомления, навигация, таймеры голосом (`AudioTrack` в режиме `VOICE_COMMUNICATION`);
* **свои рингтоны** — формат `.act` (Actions «actii», CELP, 16 кГц, 16 кбит/с, 20-байтовые кадры = 10 мс; на flash данные XOR-нуты ключом `57 2a`, магия `e1 d3` в сыром виде / `b6 f9` на разделе). Кодек и декодер уже реверсированы в `CMF-Ringtone-Tool`; заливка — через `sdfs ring1.act <size>` (уровень C);
* **музыку A2DP в часы отдать нельзя** — профиля sink нет.

## 5. Кастомные циферблаты

### Фото-циферблат (проще)

* магия `6c 8d c4 a5`; блоки `FULL 04 48 47 3a` (466×466, raw 434 312 Б) и `THUMB 04 38 c4 21` (270×270, raw 145 800 Б);
* пиксели: **RGB565-LE, top-down, сжатие LZ4**;
* поток заливки: `8052 → 9063 → A064/9064 → A065/9065`, `watchfaceId = 0xFFFFFFFF`;
* заголовок INIT2: `01 ‖ size ‖ FFFFFFFF ‖ 01 01 01 ‖ styleId ‖ posX ‖ posY ‖ color565 ‖ FF×8` — то есть позиция и цвет часов задаются при загрузке.

### Структурный циферблат (сложнее, но мощнее)

TLV-сцена (`0x20/0x21/0x22`), источники данных в `meta[9]`, кольца прогресса `0x80/0x81`, слоты `0x85/0x5f`, флаг акцентного цвета `meta[7]==4`, байт цифр `40 01 00 XX`; ассеты как `dimsWord｜len｜LZ4` с типами `cf` 4/5/13/24/1; 36-байтовый заголовок повторяется как футер; CRC32 (poly `0xEDB88320`, init 0, без финального XOR). Шрифты LVGL декодируются. Итог: можно рисовать **свои комплики с любыми данными телефона**.

## 6. Текстовые каналы («hijack» полей)

Поля, куда телефон пишет строки и которые часы просто показывают:

| Поле | Опкод | Ёмкость | Идея использования |
|------|-------|---------|--------------------|
| Город погоды | `FFFF 906B` | 32 Б | бегущая строка/статус |
| Трек и исполнитель | `FFFF 905C` | 2×64 Б | **UI диктофона**, таймеры, котировки, ETA |
| Контакты | `00D5 0001` | 20×(32+25) Б | быстрые «команды» с часов |
| Быстрые ответы | `FFFF 9073` | — | триггеры сценариев |
| Уведомления | `0065 0001` | title 20 Б + body 128 Б + иконка | произвольный текст и пиктограммы |

Это самый дешёвый способ «дописать» часам новые экраны без прошивки.

## 7. AT-канал: датчики и железо по требованию

| Команда | Ответ / эффект |
|---------|----------------|
| `AT GETVERSION`, `GETSN`, `GETNAME`, `GETPID` | идентификация |
| `AT GETBATLV` | напряжение батареи в **мВ** (точнее процентов) |
| `AT GETGSENSOR` | сырые данные акселерометра |
| `AT GETNTCTEMP` | температура NTC |
| `AT SETHR=…`, `SETHRV=…`, `SETSPO2=…` | измерение по требованию |
| `AT SETMOTOR=1` | вибро |
| `AT SETLCDSWITCH/SETGPSSWITCH/SETKEYSWITCH` | экран / GPS / кнопки |
| `AT GETSECRET` | 32 hex — ключ авторизации |

Ответы заканчиваются `,OK`. Это готовый «API железа» для отладочной панели и для сценариев (например, вибро-подтверждение записи).

## 9. Что невозможно

* музыка A2DP в часы (нет sink-профиля);
* eSIM, автономная связь;
* NFC / платежи (нет модуля; Alipay ограничен SKU);
* ЭКГ (нет датчика);
* голосовой ChatGPT (заблокирован на этом SKU: `908b = 00`);
* давление крови (ограничено SKU).

## 11. Риски и техника безопасности

1. **Уровень C — только чтение**, пока нет полного дампа flash и проверенного способа восстановления.
2. `QUICK_CARD` с некорректным `assemblyId` **затирает экраны** часов — тестировать последним.
3. OTA без подписи ≠ безопасно: неверный образ = кирпич без сервисного доступа.
4. Юридически/этически: запись звука — персональные данные. Индикация записи на часах и в шторке телефона обязательна, локальное шифрование желательно.
5. SCO-запись перехватывает аудиотракт: нельзя оставлять канал поднятым «навсегда», всегда освобождать в `finally`.
